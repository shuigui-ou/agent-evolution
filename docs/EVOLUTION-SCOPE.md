# EVOLUTION-SCOPE：范围、对象与成功判据（定义文档）

> 本文件回答"我们到底在进化什么、在哪个边界内进化、怎样算进化了"三个定义问题。
> 与 `EVOLUTION-YAML.md`（接入契约）互补：那本是"怎么接"，这本是"为什么是它"。
> 版本：v1（2026-09，出口选择环落地时确立）。

## 0. 一段话总纲

**载体（skill/agent/系统）只是携带变异的管道，不会"进化"；会延续、被选择的是载体上
可遗传变异的 知识/偏好血统；血统唯一的适应度表达，在载体出口的 结果 上。**
因此：进化 = 变异 + 遗传 + **出口选择**。没有出口选择，落地与注入只是累积（有变异、
无差分存活）——严格说不是进化。

## 1. 四个定义

| 术语 | 定义 | 反例（错的定义） |
|---|---|---|
| **载体** | 携带上下文并产出结果的代码容器：skill（管道）、agent（决策循环）、宿主系统（容器之容器）。可随时替换。 | "让 skill 进化"——skill 无自我，只有出口结果有可测属性。 |
| **血统（进化单元）** | 载体上可遗传变异的知识/偏好条目：learnings/pitfalls（fingerprint 经验）、behavior 偏好对（`dim:dir`）。跨宿主延续的是血统，不是载体。 | "跨 skill 迁移经验是顺带卖点"——它是进化的主结构。 |
| **范围（边界）** | 血统存活其上的"任务 → 输出 → 验收"回路（按输出轴 × 任务分布切），不是代码目录/进程边界。 | "让 ai-novel-studio 进化"——那是容器名，不是边界。 |
| **成功判据** | 出口结果分布被选择压力持续改善：注入后同类错误不再重犯（experience lane）、输出不再被同向纠偏（behavior lane）。 | "经验落地了 / 指引注入了 / 审计链完整"——都是管道内过程指标。 |

## 2. 目标 / 机制 / 产物（三层不混）

- **目标**：输出持续变好、错误不重犯，且无需人工调参（持续自我改进）。
- **机制**：进化 = 变异 + 遗传 + 出口选择（闭环）。"达到进化" = 环从人择闭合为出口择的
  那一刻（阶段跃迁，不是终点）；闭合后必须持续运转，**每一轮运转都是一次选择驱动的优化**。
- **产物**：优化 = 备环期人工标定 + 运转中每轮收敛，贯穿始终。停转即退化回累积。

## 3. 出口选择环（服役考核）：落地机制

给已落地条目补"服役考核"——注入后观察出口结果，按"再犯 / 不再犯"自动强化 / 衰减 / 停用。

### 3.1 生命周期状态机

```
            confirmed 累积（≥3 且 > refuted）
  active ────────────────────────────────► strengthened
    │                                          │
    │ refuted 1–2 次（且 > confirmed）           │ 后续 refuted 亦回落
    ▼                                          ▼
  decayed ── refuted ≥3（冷却期继续犯）──► retired
    ▲                                          │
    └──────────── revoke（user，计数清零）────────┘
```

- **retired 不物理删除**：账本/审计引用仍在，`revokeOutcome`（仅 user 来源）可复活；
- 状态只作用于条目（注入面/指引面），永不触碰权限档位与目标（T4 不变）；
- 阈值默认：`confirmToStrengthen=3 / refuteToDecay=2 / refuteToRetire=3 / survivalWindow=3`。

### 3.2 自动信号（宿主零新增代码）

判定"一条经验是否有效"的唯一事实 = "注入之后同类错误是否再犯"，两端引擎都拦得到：

| lane | 签发事件（开窗） | 自动 refuted | 自动 confirmed |
|---|---|---|---|
| experience（知识经验） | `preAction` 命中并注入（记 `OUTCOME_ISSUED`） | 注入后同 fingerprint 错误再 tap → `refuted`；decayed 冷却期再犯继续累计 | （无再犯由 probe/宿主确认补强；不强推弱证据） |
| behavior（偏好对） | `behaviorGuidance()` 把某对写进指引（记签发） | 签发后同对再纠偏 → `refuted` | 签发后连续 `survivalWindow` 条异维纠偏无同对再犯 → `confirmed` |

decayed = 冷却停注（指引/注入面排除，防反复唠叨同一个没用的偏好），但**保留计数**：
冷却期同因再犯仍累计证伪，3 次 → retired（彻底停用）。

宿主显式上报 `reportOutcome({lane,key,verdict})` 是可选增强（精度更细），不是必需路径。

### 3.3 与既有环的关系（无职责重叠）

- **候选裁决环**（feedback/veto/adopt/downweight）= 落地前【准入】：要不要引入这条经验；
- **出口选择环**（outcome，本文件）= 落地后【考核】：这条经验服役后有没有用。
- 两者串成完整生命周期：**准入 → 服役 → 考核 → 强化 / 退役**。
- probe/auto-rollback（宿主上报、24h 误触发率 >10% → 快照回滚）保留，处理"宿主报告的考核"；
  本环处理"引擎自动推导的考核"。回滚动快照/文件，本环管条目状态与注入面——并存不冲突。

## 4. 一条诚实的边界（防止过度承诺）

- **输出 = 载体上下文 × 基础模型 × 任务 的联合产物**：我们不能直接写"更好的输出"，只能写回
  上下文（知识/偏好）。因此变异锚定在血统上、选择锚定在出口结果上，两者不可合到一头。
- 自动"同因"判定依赖宿主在 `preAction` 与 `tapE` 使用**一致的指纹上下文**；不一致则不触发
  （fail-open，不误伤）。
- strengthened 对 behavior lane 通常需多轮生存循环或显式 confirm 才达成（弱证据不强推）。

## 5. 对外话术（取代旧口径）

旧："让 skill 获得进化能力" → 新：**"让 skill 产出的结果被出口选择持续对齐——经验越用越准、
偏好越用越贴，错了自动停用、可审计可复活。"** 载体是手段，血统是主体，出口是标尺。

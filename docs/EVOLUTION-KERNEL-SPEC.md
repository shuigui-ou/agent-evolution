# P4 进化内核运行时规范（Evolution Kernel Runtime Spec）

> 版本 v1.0 定稿 ｜ 2026-09-07 ｜ 状态：**用户已拍板 P4 档位，首宿主 = ai-novel-studio**
> 本文档是 agent 自进化系统的**唯一口径**，取代此前 ARCHITECTURE.md 中与本文冲突的部分（ARCHITECTURE.md 保留为 AED 资源层的实现参考）。

---

## 0. 第一性定义（不可再修正的地基）

| # | 定理 | 推论 |
|---|---|---|
| T1 | **进化 = 行为改变** | 没有行为改变的写入不是进化，是数据堆放 |
| T2 | **行为只能由 agent 产生** | 进化的每一个动作（感知/查/决策/落地/自评）都发生在 agent 内部 |
| T3 | **外挂无进化能力** | 外部系统（AED 等）只是内核**调用的资源**：外置记忆、分析算力、解法索引、验证服务 |
| T4 | **行为可进化，权限不可进化** | 经验内容只能改知识/策略/流程，永远不能授予工具、权限、白名单——授权只属于用户 |
| T5 | **内外驱动同链** | 自进化 = 用自己的过去教现在的我；外部驱动 = 用别人的过去教现在的我。信号来源不同，引擎、门禁、落点完全相同 |
| T6 | **进化目的 = 经济命题** | 不动模型权重的前提下，让 agent 越用越准、越用越便宜，且能力不随模型换代归零 |

**反目标**：不是规则越堆越多（budget + 淘汰）；不是替代模型训练（只作用于软件层）；不是"遇到什么都学"（每条进化必须归因到可度量的目标缺口，净收益 ≤0 的算噪音）。

## 1. 四问定稿（进化的本体论）

### 1.1 进化什么：7 类可进化单元

| 层 | 单元 | 例子 | P4 落点 |
|---|---|---|---|
| E1 | Knowledge 知识 | pitfall / guardrail / 环境事实 | 知识面（文件），支持热写 |
| E2 | Procedure 流程 | 步骤清单 / 验证流程 | 知识面流程段 |
| E3 | Policy 策略 | 触发条件 / 优先级 / 取舍规则 | 策略条目（结构化） |
| E4 | Tooling 工具 | 脚本 / wrapper / prompt 模板 | **L2 行为变更，强制人审** |
| E5 | Evaluation 评测 | 用例 / 回归集 / 负样本 | 评测集文件 |
| E6 | Context 上下文 | system prompt 片段 / few-shot | 注入文本（长度受限） |
| E7 | Meta 元进化 | 归因规则 / 门禁阈值本身 | 策略配置（**只建议，不自动改**） |

### 1.2 方向怎么定：目标栈 + 多候选 + 实证选择

1. **目标栈**：系统显式持有目标（带权重、可度量），如"压制指纹 F 复发率 RR≤5%"。
2. **方向闸**：无 objective 关联的信号只归档不进化；已达标目标自动降权。
3. **多候选**：一个信号产出 N 个候选解法（本地候选 + 解法池检索的外部同错解法）。
4. **实证选择**：G3 合成单测 + G4 影子回放各算 expected_gain，选 top1。
5. **收敛判据**：top1 expected_gain ≤ 0 → 本轮不进化，信号转人工。
6. **外部只投候选不决定方向**——方向裁决永远在本地。

### 1.3 怎么落地：三级落地态 + probe 探针

| 态 | 含义 | P4 行为 |
|---|---|---|
| L0 建议 | 只产出 recommendations，不写知识面 | 无需人审，用户/agent 自行采纳 |
| L1 注入 | 写入知识面（E1/E3/E6） | 低危自动 + 快照 + 24h 回滚窗 |
| L2 行为 | 改脚本/工具/流程（E2/E4） | **强制人审**（原语③打断询问） |

**probe 探针**：每条注入经验自带生效判据（"同 fingerprint 错误再现 → 行为是否含 fix 动作"）。命中且解决 +5 / 命中无效 −3 / 误触发 −8 / 漏触发 −1。**无 probe 的经验不允许注入。**

### 1.4 是否需要人审：权限旋钮（两维组合）

| 采纳自主度 | 行为 |
|---|---|
| `auto` | 自动落地，仅审计 |
| `auto_report` | 自动落地 + 生成报告（**推荐默认**） |
| `ask` | 原语③打断询问，附对比证据 |
| `suggest` | 只出建议不改 |
| `off` | 进化关停 |

两个固定例外（权限再高也压不住）：① L2 行为变更永远升级 `ask`；② `auto` 时落地后 24h 自动回滚窗保留。

## 2. 信号模型：错误 → 全部落差（承诺账本）

错误只是最响的信号。统一抽象：**承诺账本（Commitment Ledger）里一条 open 记录超期未闭合 = 信号**。

| 账本 | 记录 | 信号类型 | 检测层 | 默认人审 |
|---|---|---|---|---|
| 期望账本 | 用户请求中可验收要点 | G 期望落差 | L2 显式纠错+对账 / L3 语义 | 中 |
| 计划账本 | agent 声明的步骤 | P 计划偏离 | L1 计划 vs 轨迹比对 | 中 |
| 线程账本 | 开启未收尾的项目/会话 | I 悬挂未完结 | L1 生命周期巡检 | **高（必须 ask，不自动 resume）** |
| —（运行错误） | 异常/超时/exit≠0 | E 错误 | L1 机器可检 | 低 |

四类落差进同一条内核链路，处理方式一致。L3（需语义判断）复用 `ask`，把每次用户回答变成期望模型的 ground-truth。

## 3. P4 运行时六原语（宿主必须提供的接口契约）

内核 = 嵌入 agent 任务循环的模块。宿主（agent 运行时）提供以下 6 个原语；**六原语齐全 = P4**，缺哪条降哪档（见 §6）。

```ts
// 原语① 事件 tap（只读）
kernel.tap(event: RuntimeEvent): void
// RuntimeEvent = { kind: 'tool_call'|'tool_result'|'error'|'llm_call'|'task_start'|'task_end',
//                  payload, session_id, task_id, seq, ts, env }
// 所有事件流经内核，实时打标入账本。内核在此只读，不得阻塞主流程（>5ms 必须异步）。

// 原语② 前置同步 hook（可干预，P4 核心）
kernel.preAction(event: RuntimeEvent): Intervention | null
// Intervention = { kind: 'inject_guidance', text } | { kind: 'inject_fallback', plan }
// 出错当下同步查本地经验缓存：命中即注入兜底方案，不等下一轮 LLM 推理。
// 预算：单次 hook ≤ 50ms（缓存查询，不打外挂）；超时视为 null。

// 原语③ 打断询问通道
kernel.interrupt(question: { title, evidence_summary, options }): Promise<UserDecision>
// 任务中暂停 → 用户裁决 → 继续。仅用于：ask 权限项 / L2 变更 / I 型悬挂 / 冲突裁决。

// 原语④ 知识热写
kernel.write(surface_path: string, change: Patch, opts: { snapshot: true }): ApplyResult
// 只允许写白名单内知识面；写入前强制快照；写入后即刻注入当前会话上下文。

// 原语⑤ 计划 checkpoint（强制）
kernel.onTaskStart(task): RequiredKnowledge[]   // 强制读进化知识
kernel.onTaskEnd(task, outcome): SelfReport     // 强制自检对账 + 上报 + probe 记分

// 原语⑥ 审计与回滚
kernel.audit(record): void                       // hash chain append-only
kernel.rollback(toSnapshot): void                // 字节级还原
```

### 3.1 内核主状态机（八步链路，用户口述定稿）

```
事件发生(E/G/P/I) → 记录入账本(异步，不卡流程)
  → [定时批分析：本地或外挂算力] 归因 + fingerprint
  → 评估候选解法(本地生成 N 个) + 检索解法池(同 fingerprint 他人解法+命中证据)
  → 取最优(expected_gain 实证) → 权限判断(§1.4)
  → [auto] 直接落地 → [ask] 原语③打断 → [suggest] 只出建议
  → 落地(快照+热写) → 进入周期再评估(默认 7 天)
      → probe 命中且解决=保留/升级；误触发=降级/回滚；出现更优外部解法=提议升级
```

## 4. 安全约束（P4 权限最高，约束也最硬）

| 约束 | 规则 |
|---|---|
| 权限静态 | 内核与经验的任何内容**都不能**修改权限配置、工具白名单、原语开关（T4，写死在宿主层） |
| 写入白名单 | 原语④只接受声明过的知识面路径；`path.resolve` 前缀校验防穿越；拒绝写可执行文件（E4 走建议） |
| 注入防护 | 外部经验入库前过注入检测（"忽略上文"/角色劫持/数据外泄/隐藏字符/高危词）→ 命中即拒 + 贡献者扣分 |
| 频率上限 | 落地动作 ≤ N 次/天（默认 20）；超限转人审队列 |
| 快照与回滚 | 每次写入前快照；自动回滚触发：24h 内误触发率>10% / 回归集失败 / FSR 相对基线降>5pp |
| kill-switch | 一键降级 P0：内核停用，agent 回到纯知识面文件模式，**agent 本体不受影响** |
| 冷启动策略 | **不设时间窗，不设"先观测再进化"的前置期**。进化事件驱动：内部信号（E/G/P/I）随 agent 运行即时产生，单事件即可走完一轮闭环；外部候选由"主动获取 + 解法池种子预置"供给，不等自然累积。安全靠权限档（新宿主最低 suggest/ask 起步，逐档放开），FSR/RR 基线用回溯式或影子宿主 A/B 并行采集，只服务 K6 评估、不阻塞进化 |
| 审计链 | append-only hash chain，可离线校验完整性 |

## 5. 外挂资源层接口（AED 改造方向）

AED 从"进化守护服务"改造为内核的**资源服务**，只提供四类只读/受控接口：

| 资源 | 接口 | 说明 |
|---|---|---|
| 外置记忆 | `GET /resources/experiences?fingerprint=&agent=` | 经验库查询（含 credit/status） |
| 解法索引 | `GET /resources/solutions?fingerprint=` | 同错他人解法 + 命中统计 + 环境标签 |
| 定时批分析 | `POST /jobs/analyze {traces_ref}` | 归因/蒸馏/候选生成（算力外包） |
| 独立复验 | `POST /verify {experience_id}` | 信用他评（cross-validated credit） |

原则：**外挂不写任何 agent 的知识面**——落地动作全部由内核的原语④执行。外挂产出的候选只是建议，采纳与否由内核按权限旋钮裁决。

| 原语 | P4 全量 | P3 | P2 | P0 |
|---|:-:|:-:|:-:|:-:|
| ① tap | ✔ 实时 | ✔ 实时 | ✘（日志回流） | ✘ |
| ② 前置同步 hook | ✔ | ✘ | ✘ | ✘ |
| ③ 打断询问 | ✔ 任务中 | 任务边界批量 | 任务边界批量 | 只出报告 |
| ④ 知识热写 | ✔ + 会话即时注入 | ✔（下次任务生效） | ✔（工具调用时写） | ✔（外挂代写文件） |
| ⑤ 强制 checkpoint | ✔ | ✔ | ✘（提示级） | ✘ |
| ⑥ 审计+回滚 | ✔ | ✔ | ✔（apply 时） | ✔（文件快照） |

宿主声明自己支持的原语集合，内核自动启用对应档位。

## 7. 首宿主落地计划：ai-novel-studio

**为什么是它**：Node 本地服务、代码自有（六原语可加）、任务链完整（导入→拆解→生成→验证）、错误类型丰富（AI 调用失败 / 格式错误 / 长任务悬挂）。

| 步骤 | 内容 | 验收 |
|---|---|---|
| K1 | 内核库独立成包（零依赖 .cjs），实现状态机 + 账本 + 权限旋钮 + 审计 | ✅ 完成（单测 39+40 全绿） |
| K2 | ai-novel-studio 接入原语①⑤⑥（tap / checkpoint / 审计）——采集面即进化面，事件驱动当天生效 | ✅ 完成并放行 2026-09-08（宿主 14 + 集成 8 + 内核 39 全绿；真实启动冒烟通过） |
| K3 | 接入原语④ + 知识面定义（E1 知识文件）+ probe | 事件驱动：**首次 E 信号即走完整闭环**（suggest/ask 起步，无等待期） |
| K4 | 接入原语②③（同步兜底 + 打断询问），权限开到 auto_report | 出错当下能看到兜底注入 |
| K5 | AED 改造为资源服务（§5 四接口），同主多 agent 互为外驱；**解法池种子预置先行**（K2 完成即可人工灌入已知踩坑+修复，不依赖 K5） | 解法池有跨 agent 命中；首个内部错误即有候选可比对 |
| K6 | 评估：RR / FSR / 漏调用率 / 遵循率 | 回溯式基线（落地前后复发率趋势）或影子宿主 A/B 对比出报告，**不设前置基线窗** |

**事件驱动口径（§7 修订，2026-09-08）**：数据来源只有两条，都**不靠等**——①内部：E/G/P/I 随运行即时产生，一个事件就是一轮闭环的最小样本；②外部：解法池靠主动获取与种子预置供给，种子可在 K2 后立即人工灌入。进化驱动的正确形态是"每轮候选质量"问题（候选靠外供），不是"先攒数据再开跑"问题。

**指标**：北极星 = 同类问题复发率 RR(30d)；配套 = FSR、漏调用率、写入生效率（probe 命中/写入）、悬挂滞留时长、re-ask rate。

## 8. 三堵墙的对应缓解（落地推演结论，防重复踩坑）

| 墙 | 缓解（已内置本规范） |
|---|---|
| 写入≠遵循 | P4 靠原语⑤强制 checkpoint（机制而非自觉）+ probe 双账本（"写入了"和"生效了"分开记） |
| 集体确证 | 异质证据规则：同 agent×同工具链×同环境只算一份独立证据；复用验证需跨栈 |
| 自动化依赖人工 | 只自动化可验证段；L2/冲突/T3 显式设计为人审队列（原语③的固定用途） |
